## 发生了什么

DeepSeek Harness 团队 10 月 31 日晚发表技术文章《Super-agent 设计探索：迈向更自主的 Agent 系统》，并在 GitHub 同步开源配套研究原型 dsh-superagent-prototype（MIT 协议）。仓库已核实：公开可见，MIT 许可，创建于 2026-10-31T09:32:46Z。

原型是一个面向单个 GitHub 仓库的主动式编码智能体，以 DeepSeek Harness 的套件（bundle）形式提供：监听 GitHub（可选接飞书），经授权的人员提出工作请求后，它创建工作项，在独立会话与目录中干活，最后在原对话中交付，例如提交一份 Pull Request；网页面板列出需要人处理事项。

架构的核心是 Router 与 Worker 双层分离：常驻的 Router 统一接收群聊、GitHub、邮件等平台消息，维护全局上下文并分派任务；多个 Worker 各自拥有独立上下文，并发执行问题复现、代码审查、功能开发等工作，必要时调用 Subagent，Worker 不直接回复用户，只向 Router 汇报。DeepSeek 归纳 Super-agent 的四项特征：连续（多入口感觉是同一个助手）、高效（并行多任务）、主动（观察环境事件并自行推进值得处理事项）、持久（始终在线、出错可恢复）。支撑机制包括两级过滤（程序规则先筛，再由模型判断是否行动）、投机执行（例如「静默复现并修复」：确认 Bug 存在并找到简单修复后才提交，否则保持安静）、存算分离（执行循环在云端、会话状态存数据库、本地只留轻量 daemon，电脑离线任务也能继续）、独立的 Watchdog 检查无效循环，以及异步 ReAct Loop（已在 Harness 中实现，但尚未默认开启）。

必须如实注明的限定：仓库 README 首行即声明，该原型「仅供参考的研究原型，并非 DeepSeek 官方产品」，与内部版本及文章描述的实现并不完全相同，文章中的部分设计属于未来方向，尚未在原型中实现。以下实验数字均为 DeepSeek 自家模拟结果，未经独立复现：模拟约 300 条消息、约 20 条工作请求的协作环境，每种方案重复 5 次，Super-agent 任务完成时间中位数 12.4 分钟、95 分位 15.7 分钟；传统单会话方案在中性提示下 95 分位达 29.5 分钟，且 5 次实验中一次都未调用 Subagent。效率有代价：取消事件直通机制后，Router 决策次数增加约 30%，缓存读取量从 2323 万增至 3177 万 Token。DeepSeek 在文末坦言：没有提出全新理论，只是把任务调度、事件驱动、存算分离等经典计算机系统思想用到 Agent 架构上，实验也未评估真实编码质量。

## 为什么值得被历史记住

智能体时代的瓶颈正在转移：DeepSeek 团队指出的瓶颈是，AI 能完成的任务越来越多，人类管理任务的注意力却没有同步增长，一个人通常只能同时跟进 3 至 5 个活跃会话。Super-agent 把会话管理与上下文同步从人手上移到系统层面——人负责定目标和验收，调度与执行交给 AI。这是 2026 年「智能体时代」叙事的关键一环：从「AI 回答问题」到「AI 持续替人干活」，而干活的方式本身（而非又一个更大的模型）成为开源出来的成果。

与同期「把前沿模型交到所有人手里」的开源潮流一脉相承：这不是新模型、不是可订阅产品，而是一套可下载、可改造的参考架构——任何团队都能照着它搭自己的常驻编码助手，而不必把代码库交给托管服务。

## 它带来的善

小团队、学校与独立开发者可以用自己的基础设施跑一个「少打扰、多干活」的编码助手：它只在被要求或规则允许时行动，只在有人必须行动或能用上结果时才说话，人的注意力从「盯会话」回到「定目标、验结果」。对开源社区而言，参考架构公开意味着后来者不必从零摸索多智能体协作的组织方式。但生产使用仍待观察：官方明言这是研究代码、未经安全审计，接入真实仓库前须自行评审与适配。

## English version (canonical)

# 2026-11-01 · DeepSeek open-sources its Super-agent prototype: one AI manages, many AIs work

- **Date**: 2026-10-31 (official release date; Beijing evening)
- **Category**: Open source
- **Protagonist**: DeepSeek Harness team

## What happened

On the evening of 2026-10-31, DeepSeek's Harness team published the technical article "Exploring Super-agent Design: Towards a More Autonomous Agent System" and open-sourced the companion research prototype dsh-superagent-prototype on GitHub under the MIT licence. The repository is verified: public, MIT-licensed, created 2026-10-31T09:32:46Z.

The prototype is a proactive coding agent for a single GitHub repository, packaged as a bundle for DeepSeek Harness: it listens to GitHub (and optionally Feishu); when an authorized person asks for work, it opens a work item, works on it in its own session and directory, and answers in the original conversation — for example with a pull request. A web panel shows what needs a person.

The architecture's core is a two-layer Router–Worker split: a persistent Router receives messages from group chats, GitHub, email and other platforms, keeps the global context and dispatches tasks; multiple Workers, each with an isolated context, concurrently handle bug reproduction, code review and feature work, calling subagents when needed, and report to the Router rather than replying to users directly. DeepSeek names four properties of a Super-agent: continuous (many entry points feel like one assistant), efficient (parallel multi-tasking), proactive (watching environment events and advancing work worth doing), and persistent (always online, recovering from faults). Supporting mechanisms include two-stage filtering (program rules first, then a model judges whether to act), speculative execution (for example "silently reproduce and fix": only submit once a bug is confirmed and a simple fix found, otherwise stay quiet), separation of compute, state and environment (the execution loop in the cloud, session state in a database, only a lightweight daemon locally, so tasks continue while a computer is offline), an independent Watchdog against futile loops, and an async ReAct loop (implemented in Harness but not yet enabled by default).

The limits must be stated plainly: the README's first line declares the prototype "a research prototype for reference only, not an official DeepSeek product", adapted for publication so it is not identical to the internal version or to the implementation described in the article, and some designs in the article are future directions not yet implemented. The experiment figures below are DeepSeek's own simulated results, not independently reproduced: in a simulated environment of about 300 messages and about 20 work requests, each configuration run 5 times, Super-agent completed tasks with a median of 12.4 minutes and a 95th percentile of 15.7 minutes; a traditional single-session baseline under neutral prompting reached a 95th percentile of 29.5 minutes and never called a subagent in 5 runs. Efficiency has a price: without event pass-through, Router decisions rose about 30% and cache reads grew from 23.23M to 31.77M tokens. DeepSeek admits in the article that it proposes no new theory — only classic systems ideas (scheduling, event-driven design, separation of compute and state) applied to agent architecture — and that the experiment did not evaluate real coding quality.

## Why it matters

The agent era's bottleneck is shifting: as DeepSeek's team puts it, AI can do more and more tasks, but human attention for managing tasks has not grown — one person can usually follow only 3–5 active sessions. Super-agent moves session management and context synchronization from the person to the system: humans set goals and accept results, scheduling and execution go to AI. That is a key link in 2026's "age of agents" story — from "AI answers questions" to "AI keeps working for you" — and what is open-sourced here is the way of working itself, not another, bigger model.

It belongs to the same open tide as handing frontier models to everyone: not a new model, not a subscribable product, but a downloadable, modifiable reference architecture — any team can build its own always-on coding helper on it without handing its repository to a hosted service.

## The good it brings

Small teams, schools and independent developers can run a "bother less, do more" coding helper on their own infrastructure: it acts only when asked or when a team-written rule allows it, and speaks only when someone must act or can use a result — so human attention returns from babysitting sessions to setting goals and checking results. For the open-source community, a public reference architecture means later builders need not rediscover multi-agent organization from scratch. Production use remains watch-and-wait: the code is explicitly research code, without a security audit, and must be reviewed and adapted before touching a real repository.
